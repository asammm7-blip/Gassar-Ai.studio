التحديث البعيد يضم **40 ملفاً**، مع **954 إضافة و875 حذفاً**. شملت التغييرات نماذج GGUF، الوسائط المتعددة للخادم المحلي، استخراج PDF والجداول، الصوت، إعدادات EAS، حماية مفاتيح الويب، مهلات الشبكة، تنظيف الخدمات الوهمية، وتحسينات واجهة النماذج والمرفقات.

## 3. أهم المخاطر والنواقص — مرتبة حسب الأولوية

### P0 — حاجز الإصدار Web

تصدير Web يفشل في Metro بسبب محاولة قراءة `react-native-css-interop/.cache/web.css` من داخل `node_modules`. أُعيدت المحاولة بعد إزالة cache، وتكرر الخطأ. هذا يمنع اعتبار النسخة قابلة للنشر Web حتى يُعالج إعداد Metro/NativeWind أو طريقة توليد الملف المؤقت. يجب تثبيت حل دائم في إعداد المشروع أو dependency patch، ثم إعادة التصدير من بيئة نظيفة.

### P0 — الوسائط المتعددة المحلية معلنة في العقود وليست مثبتة في runtime

أضيفت أنواع `initMultimodal`, `getMultimodalSupport`, `releaseMultimodal` في `src/ml/gguf-runtime.ts`، لكن `src/ml/gguf-runtime.native.ts` لا ينفذها؛ هو يقوم فقط باستدعاء `initLlama(...)` ثم تحويل النوع Type Cast إلى `GgufContext`. عند ربط `mmproj`، يعتمد المدير على وجود هذه الدوال، وإلا يرفض التفعيل. لذلك لا يوجد في المصدر الحالي دليل أن نسخة `llama.rn 0.13.0-rc.6` توفر API Projector المتوقعة أو أن الصور/الصوت يعملان فعلياً. يلزم توثيق API المثبت، تنفيذ adapter أصلي حقيقي أو إبقاء القدرة Disabled، ثم اختبار Development Build على ARM64.

### P0 — خطأ محتمل في مسار الصور/الصوت القادمة كـ Data URL في الخادم المحلي

في `lib/local-model-server.ts` يتم إنشاء مسار من `FileSystem.cacheDirectory` ثم تمريره بصيغة `file://${path}`. مسار Expo عادة يبدأ أصلاً بـ`file:///...`، ما قد ينتج `file://file:///...`، وهو URI غير صحيح. الاختبار الحالي يثبت قبول Base64 فقط بواسطة mocks ولا يفحص المسار الحقيقي الناتج أو قراءة الصورة داخل llama.rn. يجب توحيد `file://` مرة واحدة واختبار مسار حقيقي في Native.

### P1 — إدارة ذاكرة GGUF ليست سياسة ملاءمة للهاتف

`LocalModelManager` يثبت إعدادات `n_ctx`, `n_batch`, `n_ubatch`, ويجرب `n_gpu_layers: 99` ثم يعود إلى CPU بإعدادات ثابتة. كما أن `memoryUsage` يحسب قيمة تقريبية `min(size * 0.25, 1GiB)` ولا يستخدم RAM المتاحة أو SWAP أو مساحة التخزين أو حجم KV cache. هذا لا يثبت دعم نماذج 3–10GB، وقد يؤدي إلى OOM أو إغلاق التطبيق. يلزم admission check حقيقي قبل التفعيل، تقدير معلّم يضم الأوزان/KV/buffers، اختيار إعدادات تكيفية، وقفل يمنع تبديل/حذف النموذج أثناء الاستدلال.

### P1 — قدرات النموذج مستنتجة من اسم الملف

`detectCapabilities` يعتمد على كلمات مثل `vision`, `vl`, `llava`, `embed`, `tool`، ثم `capabilitiesFromInfo` يستخدم بحثاً نصياً في JSON metadata. هذا قد يعطي false positive/negative. كما أن شاشة النماذج لا تعرض زر Projector إلا إذا أعلن الاسم Vision قبل التفعيل، وقد يمنع ربط mmproj بنموذج صالح لا يحتوي اسمه على هذه الكلمات. يجب اعتماد metadata/قدرة runtime فعلية، وإظهار Unknown بدلاً من True/False المستنتجة من الاسم.

### P1 — استخراج PDF ليس محلل PDF كاملاً ولا OCR

`document-extractor.ts` يقرأ literal strings وhex strings وFlate/ASCII85 بأسلوب regex مبسط. لا توجد معالجة موثوقة لـ`ToUnicode`, ترتيب النص، fonts، الصور الممسوحة، التشفير، الصفحات أو الجداول. كما أن hex يُحوّل مباشرة إلى UTF-16 code units تقريباً ولا يضمن العربية الصحيحة. لا يوجد OCR عربي. لذلك عبارة “دعم PDF” تعني استخراجاً محدوداً لنصوص PDF البسيطة فقط، وليست دعماً للمستندات الكبيرة أو الممسوحة. يجب تسمية الحالة بوضوح وإضافة PDF native/parser حقيقي وOCR اختياري أو رفض الحالات غير المدعومة صراحة.

### P1 — تناقض ميزانية المرفقات

التحقق العام يسمح حتى 512MB للمرفق و64MB إجمالي، لكن القراءة الفعلية للمحتوى/inline محدودة تقريباً إلى 20MB، والتطبيق يقرأ Base64 كاملاً إلى الذاكرة. هذا قد يسبب ذروة ذاكرة كبيرة، خصوصاً مع نموذج GGUF فعال. يجب استخدام streaming/chunking، وفحص مساحة القرص والذاكرة، وفصل “حجم الملف المقبول للتخزين” عن “حجم الملف المقبول للإرسال/الاستخراج”، مع عرض السبب للمستخدم.

### P1 — مفتاح Gemini يظهر في Query URL

`lib/cloud-model-service.ts` يرسل Gemini إلى عنوان يحتوي `?key=...`. حتى مع HTTPS قد يظهر العنوان في سجلات proxy أو أدوات الشبكة. يجب استخدام طريقة المصادقة الرسمية الأكثر أماناً المتاحة للمسار المختار، وعدم تسجيل URLs أو headers أو bodies الحساسة. كما أن `fetchWithTimeout` يستخدم `Promise.race` من دون إلغاء fetch الداخلي عند انتهاء المهلة؛ يلزم `AbortController` فعلي وربط مهلة الطلب بإشارة الإلغاء.

### P1 — السحابة ليست Streaming/Usage/Tools كاملة

الخدمات السحابية الحالية تنتظر JSON نهائياً، ولا تعرض SSE أو usage/finish reason أو tool-call دورة كاملة. تعريفات النماذج تعلن capabilities واسعة، لكن `generateResponse` يعيد `string` فقط. لذلك “reasoning/tools” ليست عقداً مكتملة في مسار الدردشة، ويجب إما تنفيذ النتيجة المهيكلة والبث والإلغاء الحقيقي لكل مزود أو تغيير الواجهة لتعرض القدرات المتاحة فعلياً.

### P1 — سجل المصادقة وAPI قد يكشف أسراراً

`lib/_core/auth.ts` يسجل أول 20 حرفاً من session token عند الحفظ/القراءة، ويسجل كائن المستخدم. `lib/_core/api.ts` يسجل URL الكامل، response headers، `Set-Cookie`، ونص الخطأ الخام. حتى لو لم يظهر السر في الاختبارات، هذا غير مناسب للإنتاج وقد يكشف رموز جلسات أو بيانات مستخدم في logcat/Metro. يجب حذف logs الحساسة أو استبدالها بمعرّفات redacted وبيئة development فقط.

### P1 — حساب الهوية والتحقق الخلفي ما زال غير مكتمل

يبقى `tests/auth.logout.test.ts` متخطياً لأنه يحمل TODO لتنفيذ المصادقة. نجاح الاختبارات لا يغلق دورة OAuth/logout/revocation/session expiry. يلزم اختبار integration حقيقي بعقود backend mocks صريحة، وعدم اعتبار الاختبار المتخطى نجاحاً.

### P2 — تبويب “النماذج المتاحة” يحمل روابط عامة غير دقيقة

في `app/models/index.tsx`، عند عدم وجود `downloadUrl` تستخدم الأزرار رابط Google Gemma لجميع النماذج، بما فيها OpenAI/Anthropic/OpenRouter. هذا يضلل المستخدم بأن النماذج السحابية قابلة للتنزيل من نفس المصدر. يجب جعل الرابط خاصاً بكل نموذج/مزود أو إزالة زر التحميل من النماذج السحابية وعرض “إعداد المفتاح”.

### P2 — اختيار Projector لا يتحقق من الملف بما يكفي

`selectProjector` يتحقق أساساً من الامتداد `gguf` وينسخ الملف، لكنه لا يقرأ metadata أو يطابق projector مع النموذج أو يفرض magic/signature/حجماً مناسباً. يلزم فحص GGUF فعلي وارتباط قابل للتحقق، مع rollback إذا فشلت تهيئة projector.

### P2 — توافق Android والبناء الأصلي غير مثبت

الإعداد يطلب `armeabi-v7a` و`arm64-v8a` مع llama.rn وخيارات OpenCL/Hexagon، بينما النماذج الكبيرة والاستخدام الواقعي يستهدفان ARM64 غالباً. لا يوجد في هذه المراجعة Gradle/APK أو اختبار جهاز. يلزم بناء EAS Development/Preview حقيقي، فحص ABI وHermes و16KB page-size، وتجربة استيراد نموذج 3GB على جهاز ARM64 قبل إعلان الجاهزية.

### P2 — الخادم المحلي توافق جزئي وأمان النقل محدود

الخادم يدعم مسارات OpenAI/Ollama محددة وليس استنساخاً كاملاً، ولا يستخدم TLS. Bearer token موجود، لكن LAN server يجب أن يبقى مع تحذير واضح وشبكة موثوقة، مع pairing/revoke/rotation وسقف body/backpressure واختبار عميل بطيء. الصور والمستندات لا تعني أن كل نماذج Vision/Audio ستعمل؛ يلزم ربط ذلك بقدرة runtime لا metadata فقط.

## 7. الخلاصة

النسخة المرفوعة أحدث بكثير من النسخة المحلية السابقة، وفحوص المصدر والاختبارات قوية ولا توجد أخطاء TypeScript أو lint. لكنها ليست جاهزة بعد كإصدار Native نهائي: Web export يفشل، multimodal المحلي غير مثبت على runtime، إدارة ذاكرة GGUF تقريبية، PDF/OCR محدودان، مفاتيح Gemini وlogs تحتاج تشديداً، ودورة OAuth ما زال فيها اختبار متخطٍ. التحديث الآمن تم، والتعديلات المحلية السابقة محفوظة ولم تُفقد.
