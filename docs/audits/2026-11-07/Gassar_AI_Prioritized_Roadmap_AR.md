# خارطة الإصلاح والإطلاق ذات الأولوية — Gassar.AI

**المؤلف: Manus AI. التاريخ: 7 نوفمبر 2026. خط الأساس:** `5bbeab16221b04c55657b65aba910977f4a5f287`.

## نقطة البداية وقرار الإطلاق

Gassar.AI منتج أولي وظيفي بمسارات GGUF وسحابة BYOK ودردشة ومرفقات وصوت نظامي وخادم Android حقيقية في المصدر، لكنه ليس منتجاً أصلياً معتمداً للإطلاق العام أو لوعود الخصوصية الحالية. لا توجد نسبة جاهزية ذات معنى. هذه الخارطة مبنية على مراجعة ثمانية مجالات مكتملة، وتتبع 79 معرف نتيجة أصلية مع دمج الجذور، وليست بديلاً عن [التقرير الشامل](./Gassar_AI_Comprehensive_Audit_AR.md).

**لم يُعدّل كود التطبيق أو إعداداته التشغيلية أثناء التدقيق؛ أضيفت وثائق المراجعة فقط.** تقدم HEAD المراجع كان وثيقة نطاق فقط، لا إصلاحاً. لا توجد P0 مثبتة؛ P1 مرتفع وقد يمنع شحن قدرة معينة، وP2 متوسط. `confirmed-code` ثبوت مصدر، و`reproduced-local` إعادة منطق ببدائل محلية، و`runtime-risk` أثر خارجي/أصلي غير مقاس، و`unverified-device` غياب دليل جهاز لا فشله. لا تعادل النتيجة المحلية استغلالاً حياً، ولا يضمن التدقيق حصر كل ثغرة خفية.

خط الأساس: TypeScript ناجح؛ 96 Vitest ناجحة مع اختبار مصادقة متخطى؛ 7 Python ناجحة؛ lint صفر أخطاء و33 تحذيراً؛ prebuild وWeb export وAndroid JS دون bytecode ناجحة. لا APK/AAB أو iOS archive مثبت ولا اختبار جهاز. Gradle توقف قبل Kotlin لغياب SDK، وHermes تعطل بتعارض aarch64/x86-64؛ عائق البيئة ليس عيب تطبيق مثبتاً. لذلك يبدأ العمل بإغلاق خطر البيانات وضبط النطاق، لا بإضافة نماذج أو ميزات أكبر.

## المرحلة الأولى: مانعات الثقة والخصوصية وحدود المنتج

**الأولوية الأولى: ملكية البيانات وعدم الحفظ — UI-01 وBE-02، P1 / reproduced-local.** الأدلة `lib/chat-context.tsx:203-212,360,379-449,509-515` و`lib/auth-service.ts:149-154,243-263`: الكتابات تتجاوز no-save، و`conversations` مشتركة بين الهويات، والحذف يبحث عن مفاتيح أخرى، مع سجل Gemini مكرر في `lib/gemini-service.ts:49-78,194-207`. الأثر بقاء نصوص حساسة وعرضها لحساب آخر على الجهاز، لا تسريب خارجي مثبت. الإصلاح repository موحد وسياسة احتفاظ تشمل كل العمليات وnamespace لكل حساب/ضيف وملكية ملفات وحذف منتظر. **بوابة القبول:** no-save مع الإرسال والتجديد والتقييم والتسمية لا يبقي سجلاً بعد restart؛ حسابان وضيف معزولون؛ حذف أحدهم لا يمس الآخرين ولا يعلن نجاحاً عند فشل التخزين.

**الأولوية الثانية: أسرار وهوية ونقل — CLD-01 وBE-01 وBE-03 وBE-06 وSRV-01 وSRV-02، جميعها P1؛ الثقة reproduced-local عدا BE-03 وSRV-01 confirmed-code.** الأدلة `lib/cloud-model-service.ts:93-105` و`lib/auth-service.ts:23-35,56-103` و`server/_core/index.ts:33-52` و`server/_core/oauth.ts:78-84,131-135` و`lib/local-server-settings.ts:14-21,35-43`. الجذور سر web دائم، وحساب محلي يُعامل كهوية موثقة، وCORS واسع، وlogout بلا إبطال، وHTTP/wildcard أو loopback بلا تفويض. الحل web session-only أو وسيط مفوض، وملف محلي معلن أو هوية خادمية موحدة، وclaims/إبطال وcookie host-only وallowlist/CSRF، وloopback+Bearer افتراضي ثم TLS واقتران للانكشاف. **بوابة القبول:** لا سر في المخازن الدائمة/السجلات، تعديل جلسة محلية لا يمنح مورداً محمياً، الرمز القديم يرفض بعد logout، أصل غير مقترن لا يولد ولا يأخذ credentials، والمرور المعتمد لا يكشف المفتاح. شروط استغلال الشبكة والمتصفح لم تُثبت حياً؛ الاختبارات المخولة لازمة.

**تضييق القدرات قبل الإعلان — BLD-001 P1 وBLD-004 P2 / confirmed-code؛ ATT-01 P1 / reproduced-local؛ ML-05 P2 / confirmed-code؛ CLD-04 وCLD-05 P1 بثقة confirmed-code وreproduced-local تباعاً.** الأدلة `app.config.ts:144-150`، `lib/local-model-manager.ts:320-340`، `lib/attachment-service.ts:100-137`، `lib/cloud-model-service.ts:31-80,129-145`، `lib/gemini-service.ts:63-153`. قبول اسم أو ملف أو مفتاح لا يثبت GGUF أو vision أو محتوى مستند أو اتصال مزود. الحل capability gate قبل picker، ونطاق arm64 أو 32 بت سحابي محدود، وsaved/verified/available، ورفض المرفق غير المعالج، وإزالة demo الصامت أو تسميته صراحة. **بوابة القبول:** لا نسخ محلي على Web/Expo Go/محرك غائب؛ كل مرفق مدعوم يحمل sentinel محتواه أو سبب رفض؛ غياب المفتاح/401/503 لا ينتج assistant ناجحاً؛ أسماء المزودين تختبر بحساب محدود ولا يُفترض توفر كتالوج كامل.

## المرحلة الثانية: أساس الحالة والموارد والطلب

**مدير موارد متسلسل — BLD-003 وML-01 وSRV-06، P1 / reproduced-local؛ ML-03 P1 / reproduced-local.** `lib/local-model-manager.ts:173-198,244-249,277-317,351-373` يكشف init مزدوجاً وتفعيل محذوف وتفريغ سياق جارٍ وstop يتبع نموذجاً متغيراً، والحذف لا يمحو الملف. الجذر ملكية غير ذرية للجلسة والملف. الحل queue/mutex وsingle-flight وepochs وسياق يملكه الطلب، وUUID/staging/validation/rollback وتنظيف الأيتام. **بوابة القبول:** كل deferred init/delete/switch/generate/stop ينتهي بسياق واحد، ولا release قبل انتهاء completion، وكل مهجور يحرر مرة؛ import/delete يعيدان مساحة app-owned ولا يمسان الأصل الخارجي. مقدار التسرب أو crash native غير مثبت؛ يلزم قياس هاتف لاحق.

**مخزن دردشة وطلب موحد — UI-02 وUI-03 وATT-05 وUI-04 وATT-06، P1 / reproduced-local؛ ML-04 وUI-06 P1 / confirmed-code.** الأدلة `lib/chat-context.tsx:113-165,299-366,428-503` و`lib/model-settings-storage.ts:4,22-39`. الأثر ضياع البدائل وإلحاق رد A بـB ومسح المسودة وتبديل اتصال التجديد وفقد المرفق وإعدادات لا تصل. الحل مصدر normalized مع currentConversationId مشتق، وحفظ بعد hydration، وrequestId/conversationId وقفل قبل await، وbuilder واحد للإرسال/التجديد/settings والمرفقات، ونتيجة typed بدلاً من نجاح void. **بوابة القبول:** التنقل والحفظ المعكوس لا يفقدان التعديل؛ رد A لا يدخل B؛ الضغط المزدوج طلب واحد؛ الفشل يبقي المسودة؛ auto+local لا يستدعي السحابة؛ السؤال مرة والمصدر موجود في الإعادة؛ أول payload بعد الإعدادات يطابق القيم. لا يُكتفى بإصلاح dependency واحدة مع بقاء المخزنين.

**عقد تخزين ومرفقات — ATT-02 وATT-03 وATT-08، P1 بثقة reproduced-local وconfirmed-code وreproduced-local؛ ATT-07 P2 / runtime-risk وUI-12 P2 / confirmed-code.** الأدلة `lib/attachment-service.ts:46-70,107-138` و`lib/chat-context.tsx:203-217` و`node_modules/expo-file-system/src/legacy/ExponentFileSystemShim.ts:5-12`. الحل adapter typed للـImagePicker وreader native/Web وحجم حقيقي وحصة مجموع/عدد وأصول دائمة اختيارية وschema/migrations. **بوابة القبول:** fileSize الزائد وmetadata المضللة تمنع القراءة؛ المتصفح يرسل sentinel TXT/PDF/PNG؛ بيانات object/null لا تنهار؛ المرفق المتعهد بحفظه يبقى بعد restart وتنظيف cache، وحذفه يحفظ أصول المستخدم. ثم تغلق تصادمات الأسماء والامتداد وURI في ATT-09/10 وML-08/09 باختبارات regression المحددة في التقرير.

## المرحلة الثالثة: ميزانيات الهاتف والإلغاء ودورة الخدمة والصوت

**الموارد وعقد النهاية — BLD-002 وML-02 P1 / runtime-risk؛ ML-06 P1 / reproduced-local؛ CLD-03 P1 / reproduced-local وCLD-08 P2 / reproduced-local؛ ML-07 P2 / reproduced-local.** `src/ml/model-safety.ts:26-35` و`lib/local-model-manager.ts:214-249,286-317` و`lib/cloud-model-service.ts:152-263` يخلطان حد الملف بملاءمة RAM ويختزلان النتيجة إلى نص بلا signal وtoken budget. الحل admission للقرص والأوزان وKV/buffers والbackend، وإعداد سياق متكيف، وtoken reserve وpartial/finish/usage، وإلغاء من قبول الطلب وdeadline وretry محدود لا يكرر تكلفة غير محسومة. **بوابة القبول:** الصغير يعمل وغير الملائم يرفض قبل init؛ ذروة PSS/RSS وTTFT والحرارة مسجلة على فئات RAM؛ prompts عربية قرب الحدود ضمن الميزانية؛ abort قبل init يمنع completion وبعدها يمنع commit المتأخر؛ طلب شبكة عالق ينتهي ويعيد الواجهة. قبول 10GiB في اختبار metadata ليس تشغيله.

**الخادم الأصلي — SRV-05 P1 / reproduced-local؛ SRV-07 P1 / runtime-risk؛ BLD-006/SRV-08 P2 / confirmed-code؛ SRV-03/04/09 P2 / reproduced-local؛ SRV-10 P2 / confirmed-code.** الأدلة `lib/local-model-server.ts:218-324,326-370,487-654` و`modules/gassar-device-telemetry/android/src/main/java/com/gassar/device/telemetry/GassarServerService.kt:30-75,114-120`. الحل start/stop operationId عبر كل await، وFGS ack/error/stopped، وإنفاذ سقف body/output وحصص اتصالات وschema خيارات، وwakelock محدود بالحاجة وقياسات sampledAt. **بوابة القبول:** stop في كل نقطة بدء يترك صفر موارد؛ running لا يظهر بلا FGS مؤكد؛ pause بعد الجاري يحرر القفل؛ زيادة بايت/رمز ترفض قبل المولد؛ عميل بطيء لا يحتكر المتابعة؛ stale ظاهر وخيارات غير منفذة تعيد4xx. iOS foreground-only أو معطل صراحة وفق BLD-005 P2 / confirmed-code، لا خدمة Android مفترضة.

**صوت النظام أولاً — VOC-01/02/07 P1 / reproduced-local؛ VOC-04/10 P1 / confirmed-code؛ VOC-05 P1 / runtime-risk.** الأدلة `lib/tts-service.ts:21-80` و`app/voice/index.tsx:31-36,296-330` و`app/chat/[id].tsx:61-64,194-224` والتبعية `ExpoSpeechService.kt:92-110,387-391`. أصل المشكلات defaults صامتة وطابور لا يلغى وبديل STT خاطئ وشاشة بلا رد ومسار on-device غير مضمون على31/32. الحل parsers ومديرا TTS/STT بمالك/جيل، وresults[0] ونهائي محفوظ، وصوت جهاز متحقق، وتكامل on-device مصحح أو منع صريح للإصدارات غير المضمونة. **بوابة القبول:** defaults مسموعة وstop لا يكمل المقاطع؛ العربية أو خطأ صريح؛ instrumentation ووضع طيران وtraffic لمرحلة STT؛ لا دعوى local-only من preferOffline. بعد ذلك VOC-03/06/08/09 وUI-09 تغلق pause الوهمي والجاهزية وطمس المسودة وauto-read القديم. **لا نموذج STT كبير مضمّن إلزامياً؛ حزمة لغة النظام بموافقة المستخدم هي المسار المتفق عليه.**

## المرحلة الرابعة: تحقق الأمن وسلسلة الإصدار

تغلق BE-04 P1 / runtime-risk وBE-05 P2 / reproduced-local مع اختبار OAuth state/claims وcallback والهوية الخادمية؛ BE-08 P2 / reproduced-local مع readiness/503 وحفظ المستخدم قبل نجاح login؛ CLD-02 وBE-07 P2 مع redaction، وCLD-09 P2 / runtime-risk مع قرار Anthropic web واختبار CORS. الأدلة `server/_core/sdk.ts:189-205,252-279`، `app/oauth/callback.tsx:33-67`، `server/_core/index.ts:59-79`، `lib/_core/api.ts:35-58`، `lib/cloud-model-service.ts:232-258`. **بوابة القبول:** رموز wrong-app/missing-exp وstate المنقول/المكرر ترفض؛ outage يعيد503 لا نجاحاً ثم401؛ بيانات اعتماد اصطناعية لا تظهر بأي سجل؛ web/native نجاحان مستقلان لا افتراض بروتوكول واحد.

**BE-09 P1 / confirmed-code؛ BE-10 P2 / reproduced-local؛ BLD-007 P2 / confirmed-code:** تثبت وجهة Git الوحيدة وجميع URLs، والفحوص على snapshot SHA لا ROOT الحي، ونسخ الأدوات وصورة البناء وfrozen lockfile. الأدلة `scripts/github-sync.py:37-44,76-96` و`eas.json:1-23`. القبول fixture أول عنوان صحيح وثان خاطئ يرفض بلا نقل، وتغير worktree لا ينسب النجاح لشجرة أخرى، وskip-checks بلا attestation لا يصبح Verified.

## المرحلة الخامسة: صدق الاستعمال ثم الإضافات

تغلق UI-07/08/10/11، جميعها P2، بثقة reproduced-local للأولى والأخيرة وconfirmed-code للباقي: تسمية وترتيب ومفضلة ومؤشر اتصال، وتفضيلات تطبيقية وترجمة ومظهر، وsheet متجاوبة ووصول، وترحيب بانتقال محدود. الأدلة `app/(tabs)/index.tsx:101-112,265-304` و`lib/theme-provider.tsx:14-40` و`components/model-dropdown.tsx:108-138` و`components/startup-welcome.tsx:69-103`. القبول من جهاز صغير/أفقي وخط كبير وTalkBack/VoiceOver، مع English فعلي وRTL ونص مختلط ومظهر مستعاد وترحيب لا ينهار بالضغط المتكرر.

بعد الجذور، أفضل حزمة توسع هي: مركز قدرات وتشخيص ونسخة إصدار قابلة للتتبع، بكلفة متوسطة واعتماد على القياسات وartifact؛ ومركز export/restore مع manifest وتشفير اختياري واستبعاد الأسرار، بكلفة متوسطة إلى مرتفعة واعتماد على ملكية البيانات؛ وبث وإيقاف ونتيجة structured، بكلفة متوسطة واعتماد على request lifecycle. هذه الثلاث قيمة P1 ولا تعوض الإصلاحات الأساسية.

تليها جاهزية صوت النظام وحلقة نصف مزدوجة بكلفة متوسطة، ثم استخراج/OCR عربي بمصادر بكلفة مرتفعة، ثم RAG بكلفة مرتفعة يعتمد على الاستخراج وembedding budget وفهرس يحذف مع المصدر. الرؤية المحلية اختيارية بكلفة مرتفعة بعد projector وruntime وصورة pixels مختبرة، لا بعد تغيير الأعلام فقط. الاقتران وإدارة الأجهزة والجلسات بكلفة متوسطة إلى مرتفعة بعد TLS والإبطال، ومكتبة السجل والفروع وMarkdown العربي الآمن بكلفة مماثلة بعد normalized state، ولوحة موثوقية المزامنة والطاقة بكلفة متوسطة بعد SHA وFGS وعمر العينات؛ هذه تكمل **عشر إضافات مختارة** ذات P2 بعد الأساس. لكل إضافة اختبار قيمة: round-trip استعادة، أو sentinel مستند واستشهاد صحيح، أو إبطال عميل، أو فرع تحرير صحيح، أو تشخيص لا يحمل prompts/أسرار. الأدوات ذات الأثر تؤجل إلى P3 بصلاحيات وحدود تكلفة، لا تُحسب منفذة حالياً.

## شروط الإغلاق وفجوات الدليل

إغلاق أي بند يحتاج commit إصلاح وregression test، ثم artifact ومحضر جهاز عندما يمس native أو المنصة. الحواجز الموجودة فعلاً كـoptional module وchecksum وتأجيل JSI وخدمة غير مصدرة ليست عيوباً غائبة؛ لكنها ليست نجاح native مثبتاً. لا إصلاح وظيفي لاحق موثق للنتائج في المدخلات.

لا map failures، لكن التحقق الناقص يشمل الأجهزة والمتصفح وSecureStore ودوام URI والصوت وذاكرة/حرارة/GPU، والنماذج السحابية الحية وحساباتها وCORS، وOAuth provider والـDB/الـproxy، وEAS/Play والتوقيع وCI وحماية الفرع وbackup خارجي وURLs Git الفعلية. لم تقرأ مراجعات الوحدات أسراراً ولم تنفذ دفعاً أو هجوماً. تحقق المنسق لاحقاً من أن عناوين fetch/push الحالية وجهة واحدة معتمدة؛ مزامنة وثائق التقرير خطوة تسليم مستقلة لا إصلاحاً للبرنامج. لا نعد Git backup المصدر backup بيانات؛ يلزم مشغل وخطة RPO/RTO وتمرين استعادة للـDB المنشورة. تُقبل المخاطر المتبقية فقط بقرار نطاق معلن، لا بإخفائها وراء نتائج JS الخضراء.
